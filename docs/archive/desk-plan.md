# 桌面-only 推进路线（无法下场时）

> 前提：暂时不能去场地，只能在桌面模拟。车可能没有实体或不能完整运动。
> 目标：把「软件接线 + 模型映射 + 几何换算 + 扫码距离」在桌上证明；把必须场地的项记入 gaps，不假装已经覆盖。

---

## 桌面能证明 / 不能证明

| 能在桌上证明 | 不能在桌上证明（记入 gaps） |
|---|---|
| 模型加载、class_id→业务ID 映射 | 真实场地光照与反光 |
| 数字框粗定位 +（可选）外扩环拟合的**相对**精度 | 底盘运动中的伺服收敛 |
| 尺度标定 `scale`（尺子 + 打印靶标） | `dir` 方向标定的完整矩阵（需机器人能动） |
| K210 扫码距离（QVGA/VGA） | 启停区→扫码位的实际走位 |
| 串口协议（USB 串口助手模拟主控） | L4/L5 上车成功率 |
| gate 集回归（同高度、同镜头） | 黑障碍与黑物料在真实背景下的混淆 |

**铁律不变**：几何不变量（相机高度/俯角/镜头）桌面也要定死并写进 `config`；改了就重录 gate。

## 桌面最小道具清单（按优先级）

| # | 道具 | 用途 | 没有会怎样 |
|---|---|---|---|
| 1 | 按图二**1:1**打印的环台图案（580×150，三环，含虚线环与数字） | 映射验证 + 精修实验 | 环精定位无法做 |
| 2 | 尺子 | 尺度标定、量打印是否缩水 | 标定不可信 |
| 3 | 80mm 二维码打印纸（内容用规则样例 `156+123+516+231`） | K210 距离实测 | 扫码距离只能猜 |
| 4 | 6 色物料（最好真实 3D 打印件；至少色卡纸近似） | 颜色映射验证 | 颜色链路卡死 |
| 5 | 三脚架/书本堆：把 MaixCAM 固定到**计划放置高度** | 几何不变量 | 数据以后全废 |
| 6 | USB 串口助手（电脑端） | 当「假主控」收发 | 只能看屏幕 log |

> 打印注意：必须按 mm 真实尺寸，关闭「适应页面」。量一下 300mm 两端心距是否真是 300mm；缩水超过 1% 就重打。

## 桌面推进顺序（每步一停，可验收）

### 步 D0 · 固定几何（今天就能做，30 分钟）

1. 决定一个放置高度，例如 300mm 或 350mm（写进 `config.CAM_HEIGHT_MM`）
2. 俯角尽量接近实际：若相机在立柱前支架，用 CAD 估一个俯角写进 `CAM_PITCH_DEG`
3. 用胶带在桌上标出相机正下方的投影点，方便以后重复摆放

验收：`config.py` 里高度/俯角不再是 `None`。

### 步 D1 · 板上加载模型 + 验证业务ID（最重要）

1. 把两个 `.mud` + `.cvimodel` 拷到 MaixCAM
2. 填 `MODEL_CONF_TH`（建议先 0.45）、`MODEL_IOU_TH`（建议先 0.45）——这是起点，不是最终值
3. 跑验证脚本（见下）：屏幕上画框，**旁边写业务ID**，不要写 class_id
4. 用打印环：对着数字 1/2/3，确认输出 `c:1/2/3`
5. 用色块/物料：红→1，蓝→3，浅蓝→6

验收：三组颜色 + 三个环号全部肉眼正确。  
**未通过前不要录 gate。**

### 步 D2 · 串口当主控（电脑模拟）

1. MaixCAM / K210 用 USB 转串口接到电脑
2. 串口助手：看视觉端持续输出 JSON；手动发 `SET:RING` / `SET:MAT`
3. K210：用打印二维码，看是否发出 `$156+123+516+231#`；助手回 `$ACK#` 应停止重发

验收：协议双向跑通，与场地无关。

### 步 D3 · 尺度标定 `scale`（不需要车）

1. 桌上放两个标记，尺子量准 100mm
2. `python calib_task.py scale --len-mm 100`
3. `python calib_task.py phys --height-mm <你的高度> --pitch-deg <你的俯角>`

验收：`calib.json` 里有对角矩阵；`config` 加载后打印矩阵。  
说明：没有 `dir` 时矩阵假设轴对齐，**只能用于桌面估误差，不能当真车上伺服用**。

### 步 D4 · 扫码距离实测（K210，纯桌面）

1. 80mm 二维码贴墙/立着
2. QVGA、VGA 各测一遍：从 1.2m 每次靠近 10cm
3. 记录「连续 3 秒稳定 LOCK」的最近距离

验收：两个数字写进 `vision_qr/README.md`。用实测排流程，不用估算。

### 步 D5 · 桌面 gate 集（5～10 张就够）

拍什么（同一高度、同一俯角）：

| 样本 | 期望 | 目的 |
|---|---|---|
| 环 1/2/3 各一张，环在画面中心附近 | `c` + 环心大致在中心 | 映射 + 粗定位 |
| 环偏左/偏右各一张 | `ex/ey` 符号方向对不对 | 符号自检 |
| 红/蓝/浅蓝各一张 | `c:1/3/6` | 颜色映射 |
| （若有）黑圆柱障碍一张 | **不应**报成颜色 5，或面积被滤掉 | 负样本 |

文件名建议：`ring_1_center.jpg`、`mat_3_blue.jpg`、`neg_black_obstacle.jpg`。

验收：目录里有图；每张你知道正确答案（人工，不是模型输出）。

### 步 D6 · `eval_task.py`（我写，你跑）

扫 `data/gate` → 打印每张的检出 / 业务ID是否对 /（若有标定）像素误差。  
验收：改阈值前后能对比；映射错误会被抓出来。

### 步 D7 · 可选：外扩环拟合（仅当 D5 显示粗定位不够）

用打印的虚线环图，在数字框外扩 ROI 里拟合圆心。  
桌面验收：环心相对打印图几何中心的误差（尺子 + 打印已知尺寸）。

## 明确不做的事（避免浪费桌面时间）

- 不上车调 PID / 完整任务状态机联调
- 不追求「复现赛场光照」
- 不做 `dir` 标定（没有可靠平移源就别硬做；会得到错误矩阵）
- 不把桌面 `scale` 矩阵当成决赛可用标定
