## 2. 精度分析：视觉不是瓶颈，机制才是

### 2.1 计分环换算（我的解读，**必须验证**）

按「每环直径比上一环增加 N mm」推算，`φ` = 物料尺寸：

| 环 | 直径公式 | 直径 | **径向余量** | 得分 |
|---|---|---|---|---|
| 1环 | φ+3 | φ+3 | **±1.5mm** | 15 |
| 2环 | φ+8 | φ+8 | **±4.0mm** | 10 |
| 3环 | φ+15 | φ+15 | ±7.5mm | 7 |
| 4环 | φ+25 | φ+25 | ±12.5mm | 5 |
| 5环 | φ+35 | φ+35 | ±17.5mm | 3 |
| 6环 | φ+45 | φ+45 | ±22.5mm | 1 |
| 外/倾倒 | — | — | — | 0 |

> 关键：径向余量与物料尺寸**无关**，恒为 +3/+8/+15/+25/+35/+45 的一半。

### 2.2 这个数字意味着什么

**1环 = ±1.5mm 中心精度。** 对轮式机器人 + 开环定位，这个量级基本不可能。

**2环 = ±4mm** 是现实目标。1环应当视为「可以博，但不能依赖」。

### 2.3 视觉分辨率够不够：够，而且富余

下视相机，1080p，水平视场 60°：

| 相机高度 | 视野宽度 | 分辨率 | 判断 |
|---|---|---|---|
| 150mm | 173mm | 0.09 mm/px | 远超所需 |
| 300mm | 346mm | 0.18 mm/px | 远超所需 |
| 500mm | 577mm | 0.30 mm/px | 仍够 |

**结论：只要相机离目标 500mm 以内、俯视，视觉精度可以达到亚毫米。±1.5mm 的瓶颈不在这里。**

### 2.4 真正的瓶颈（按影响排序）

| 瓶颈 | 量级 | 对策 |
|---|---|---|
| **手眼标定误差**（相机光轴 ≠ 夹爪中心） | 数 mm | **必须做手眼标定**，这是本项目新增的必做项 |
| 机械臂/升降机构重复定位 | 1~5mm | 机械精度决定上限，视觉再好也救不了 |
| 松手瞬间物料滑移 | 1~5mm | 降低释放高度、缓释放、释放后不复位 |
| 底盘位姿漂移 | 数 cm | **必须闭环视觉伺服**，不能「量一次→开环挪过去」 |
| 圆环本身印刷/贴装误差 | <1mm | 实物测量确认 |

### 2.5 由此推出的架构结论

> **必须做闭环视觉伺服：看 → 动一小步 → 再看 → 再动。**
> 不能做「全局定位一次 → 计算出坐标 → 开环移动到位置」。

理由：底盘位姿误差是数 cm 量级，而目标是 ±4mm。开环无论如何达不到。闭环后，底盘误差被视觉吸收，只需要「能看见环」即可。

## 3. 三个架构选项（这才是先要定的事）

### 方案 A：双相机 —— 前视 + 下视

| | 前视相机 | 下视相机 |
|---|---|---|
| 装哪 | 车体前部，俯角约 30-45° | 夹爪/机械臂末端，垂直向下 |
| 干什么 | V1 二维码、V4 车道、V5 障碍、远场找物料 | V2 颜色精识别、V3 圆环精定位 |
| 精度 | 不需要高 | 亚毫米 |

- **优点**：各司其职，精度最好，视觉伺服天然由下视相机完成
- **缺点**：两个相机 → 两套标定、两套时间戳、两路 USB 带宽
- **需要**：能做手眼标定的机械臂

### 方案 B：单相机 + 机械被动对中

- 前视相机只负责「大致对位」（±10~15mm）
- 靠**自定心夹爪 / 导向漏斗 / V 型槽**把物料机械地推到中心
- **优点**：视觉压力骤降，标定简单，成本低，鲁棒
- **缺点**：换物料形状就失效（决赛有圆柱/方形/三角/球体/锥体 → **被动对中很难兼容全部形状**）
- **判断**：初赛统一形状 → 可行且有性价比；决赛多形状 → 会撞墙

### 方案 C：单相机 + 纯开环

- 不推荐。±4mm 达不到，且误差不可观测。

### 方案 D：单相机装在可俯仰云台

- 一个相机两用：平视扫二维码，俯视做精定位
- **优点**：省一个相机，省一套标定
- **缺点**：云台角度必须可重复（否则等于换了相机位姿，标定失效）

> **我的建议**：如果机械臂已经在做 → A；如果还没有机械臂、想用最简单的方案 → B（并接受决赛要改）。这是取舍，不是标准答案。

## 4. 已确认的约束（2026-10-28）

| 项 | 答案 |
|---|---|
| **职责** | 只做视觉；整场流程归**主控**；视觉端保留**薄状态机**只管「当前在看什么」 |
| **相机方案** | 双相机：**MaixCAM Pro 下视**装夹爪（物料/圆环）；**K210 平视**只做扫码 |
| **计算平台** | MaixCAM Pro 为视觉端；K210 独立扫码节点 |
| **机械** | **小车尚无实体，只有结构图** |
| **场地** | 赛前只能拿到**几小时** |

**这三条约束的组合后果**（详见 `docs/arch-v1.md`）：

1. **无车 → 契约必须输出「增量误差」而非「绝对坐标」**，否则手眼标定做不了
2. **无车 → 相机安装高度/俯角必须先定死在数字上**，用三脚架按计划位置录数据
3. **几小时场地 → 现场只采集不开发**，必须提前写好现场协议
4. **±4mm 的瓶颈是机械不是视觉**，现在就要向机械那边索取重复定位精度

> 架构、契约、骨架、标定流程、风险登记 → `docs/arch-v1.md`

| R9 | 单次比赛总时长、单批时间限制 | 决定砍不砍功能 |

```text
【层 1 约束·不可改】
  - 输出结构见 core.py 的 VisionMsg，单位 mm，坐标系 ⟨待定：相机系/车体系⟩
  - 角度用 ⟨弧度/度⟩，正方向为 ⟨逆时针/顺时针，从上方看⟩
  - 单帧耗时 ≤ ⟨x⟩ ms
【层 2 要求】
  - 必须能离线回放：tools/eval.py --data data/gate 跑完输出 PASS/FAIL
  - 参数全部从 config.yaml 读，代码里不出现魔数
  - 日志每帧打印：frame_id / t_capture / t_proc / 检测到的环心 px / 换算后的 mm
【层 3】不限制，但需说明选型理由与已知失效条件
【验收】gate 集上环心误差 ≤ 1.5mm 的帧占比 ≥ 90%（对应 L2）
【本次只做】只做「给定单张静态图输出环心像素坐标」，先不接相机、不做 mm 换算。
做完停下汇报，给出三行：改了什么 / 我假设了什么 / 我给什么加了限制。
```
